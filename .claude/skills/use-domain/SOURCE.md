# Откуда здесь MCP Cloudflare и что в нём наше

**Этот навык — НАШ, и его никто не перезаписывает.** Чужого кода в папке нет: сервер MCP живёт не
файлом, а адресом в `.mcp.json` корня, и обновляет его Cloudflare на своей стороне.

| | |
|---|---|
| сервер | `cloudflare-api` → `https://mcp.cloudflare.com/mcp` |
| что умеет | по документации Cloudflare — «более 2500 эндпоинтов: DNS, Workers, R2, Zero Trust и остальные продукты» через два инструмента: `search()` и `execute()` |
| вход | OAuth: человек выбирает права в окне Cloudflare. Ключей у нас не хранится |
| взято из первоисточника | `developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/`, прочитано 2026-09-21 |
| заведено | шаг 259-6, по слову владельца: «скилл и MCP должны идти в комплекте с нашим приложением для всех пользователей» |

## Чего этот сервер НЕ решает, и это важнее того, что решает

🛑 **Он не участвует в работе сайта.** Туннель поднимается при загрузке компьютера, когда рядом нет
ни агента, ни человека у браузера; OAuth требует обоих. Поэтому всё, что обязано работать само,
построено дверями узла (`app/api/domain/*`) и ходит в API Cloudflare с токеном.

🔒 **Это прямое следствие закона о единой точке отказа** (решение владельца 2026-09-18): «что
перестанет работать у пользователя, если Fractera исчезнет завтра?» — правильный ответ «ничего», и
он обязан оставаться правильным, если завтра исчезнет чужая служба MCP.

## Второй сервер Cloudflare существует и НЕ подключён намеренно

`https://dns-analytics.mcp.cloudflare.com/mcp` — разбор производительности DNS. Он про другую задачу:
оптимизацию, а не подключение. Понадобится — добавляется строкой в `.mcp.json`; лишний сервер в
комплекте у каждого пользователя стоит внимания агента на каждой сессии.
